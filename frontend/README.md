# Есть место

Сервис для поиска и бронирования рабочих мест в коворкингах. Сейчас в репозитории находится фронтенд MVP для выбора коворкингов в университетском кампусе.

## Возможности фронтенда

Интерактивный выбор 23 коворкингов кампуса. Комнаты детерминированно перемешаны между этажами: 8 на первом, 8 на втором, 7 на третьем.

## Оформление и компоненты

Оформление согласовано с [личным кабинетом студента УрФУ](https://istudent.urfu.ru/): белые карточки на светлом фоне, синяя навигация, розовые основные кнопки и жёлтые плашки. Логотип взят с публичной главной страницы университета; Open Sans и Open Sans Condensed — из её публичного набора шрифтов. Ресурсы сохранены в `public/urfu-logo.svg` и `public/fonts/`, поэтому интерфейс не загружает их с внешнего сайта. Это демонстрационный проект учебных пространств; вход в личный кабинет остаётся внешней ссылкой на сайт УрФУ.

Правило разработки: новые повторяющиеся элементы выделять в переиспользуемые компоненты, не копировать разметку кнопок, карточек и блоков между страницами. Сейчас общая шапка, навигация и подвал находятся в `components/site-shell.tsx`, карточка комнаты — в `components/room-card.tsx`, выбор роли — в `components/role-select.tsx`, сводка рейтинга — в `components/rating-summary.tsx`, а подробные правила — в `components/additional-info-dialog.tsx`. Для новых обычных кнопок использовать существующий `components/ui/button.tsx`. Цвета и шрифты задавать через общие переменные в `app/globals.css`.

## Запуск проекта

Нужны Node.js 22.13+ и pnpm. Для встроенных тестов TypeScript рекомендуется Node.js 22.18+.

```sh
pnpm install
pnpm dev
```

Откройте адрес, который напечатает сервер. Команды проверки:

```sh
pnpm exec tsc --noEmit
pnpm build
```

## Поведение

- Зелёный: свободно на выбранные дату и время.
- Красный: выбранное время попадает в занятой интервал.
- Жёлтый: следующий занятый интервал начинается в течение 30 минут.
- Схема и список, переключение этажей, выбор времени и даты, фильтр свободных комнат, карточка с расписанием на день.
- В схеме фильтр приглушает недоступные комнаты, сохраняя расположение; в списке скрывает их.
- Дата и время на главном экране необязательны: до их выбора карточки нейтральные, после выбора показываются статусы и легенда занятости.
- В профиле можно выбрать роль ученика или преподавателя. Для ученика начальный рейтинг равен 0: завершённая бронь даёт +1, одна отмена в месяц бесплатна, отмена более чем за 2 часа до начала не меняет рейтинг, последующие поздние отмены дают −2.
- Рейтинг не блокирует аккаунт: при отрицательном рейтинге ученику закрыт доступ к пяти самым востребованным коворкингам, менее востребованные остаются доступны. У преподавателя рейтинг не влияет на доступ.
- Каждая успешная бронь добавляет выбранному коворкингу один скрытый балл на 30 дней; по этим баллам формируется список самых востребованных пространств.
- Форма бронирования проверяет имя, цель, количество участников в пределах вместимости, длительность от 30 минут до 4 часов и правило «один аккаунт — один активный коворкинг».
- Для выбранного коворкинга в демо действует правило «один ответственный на слот»; окончательная проверка должна выполняться на сервере.
- «Мои бронирования» позволяет посмотреть рейтинг, количество участников, активную бронь, историю и отменить бронь. Подробные правила доступны в боковой кнопке «Доп. информация».
- Брони хранятся только в `localStorage` текущего браузера. Это временная клиентская реализация: авторизация, общий серверный API, база данных и защита от конфликтов между пользователями пока не подключены.

## Подключение бэкенда

`lib/campus.ts` содержит типы комнат, тестовые данные, генерацию расписания и расчёт статусов. Замените этот источник запросами к API каталога и доступности. При подключении запросов добавьте состояния загрузки и ошибки; при ошибке подтверждение должно быть недоступно.

`app/page.tsx` содержит пользовательские действия и интерфейс. Демо-операции бронирования вынесены в `lib/bookings.ts`; при подключении сервера этот модуль нужно заменить адаптером к API, сохранив серверную проверку конфликтов.

Фронтенд построен на React, TypeScript и совместимом с Next.js App Router фреймворке Vinext. Vite/Sites-конфигурация используется для предпросмотра и размещения; прикладного бэкенда нет.

`hooks/use-campus-tools.ts` опционально регистрирует WebMCP-инструменты чтения комнат и выбора комнаты в поддерживающем браузере. Проверены регистрация обоих инструментов, чтение 23 комнат, выбор комнаты другого этажа, отклонение неверных параметров и сохранение состояния после ошибки. Обычный интерфейс от этих инструментов не зависит.

## Планируемый MVP с бэкендом

- каталог коворкингов;
- просмотр свободных рабочих мест;
- выбор даты и часового слота;
- бронирование места;
- просмотр и отмена своих бронирований;
- защита от двойного бронирования одного места на один слот.

Интеграции с реальными площадками, оплатой и внешними системами бронирования пока не входят в MVP. Если данные о доступности не загрузились, сервис должен показывать сообщение об ошибке и временно отключать бронирование.
